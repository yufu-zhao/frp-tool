## 2026-11-24 本机证书闭环（80/443 空闲 → frps 直占 → 本机终止 HTTPS）

延续上一段路线，把「80/443 空闲时证书落在本机、由 frpc 终止 HTTPS」从签发引擎接到 frpc 实际启动，形成闭环。

### 实现要点

- `serverCertificateSchema` 新增 `location: 'local' | 'server'`（默认 `server`）与 `localCertificateId`，用于区分证书落在服务端还是本机。

## 2026-11-25 TLS 双方案自动判定（服务器终止 / 本机终止）

- 判定规则只有两个条件：服务器探测到 Web 服务（Nginx/OpenResty/Apache）+ include 注入记录存在且 `default.conf` 探针生效 → 方案 A（服务器终止 TLS）；其余一律方案 B（本机 frpc `https2http` 终止）。443 占用 / 多域名 / 权限等因素只做 `TlsPlan.warnings` 提示，不参与决策、不自动处理。
- 新增 `src/shared/tls-plan.ts` 的 `decideTlsPlan()` 为单一判定源；主进程 `tls:plan` IPC 与渲染层共用同一函数。实时 probe 优先于注入记录快照。
- 方案 A 签发链路：DNS-01 或 HTTP-01 拿到 PEM 后，工具把证书写到服务器 `/etc/intranet-frp/sites/nginx/certs/<id>.crt|.key`，生成 `listen 443 ssl` 的 server 块写入注入目录，`nginx -t` 校验 + reload；规则自动切成 http 回源 + `publicHttps` 标记，frpc 不再持证书。
- 方案 A 的 HTTP-01：在注入目录临时部署 `server_name` 精确匹配的 challenge server 块，token 由工具 SSH 写到 `/etc/intranet-frp/acme/.well-known/acme-challenge/`，签发完成后移除临时 server 块；不占用其它域名的 80 路径。
- 方案 B 保持原有本机证书 + frpc `https2http` + nginx stream 透传链路；HTTP-01 沿用 frpc 临时通道。
- 任一环节失败都按快照回滚：DNS TXT、challenge server 块、服务器证书/私钥/server 块、规则类型与证书引用、store 记录。
- store schema 升到 4：清空旧 `certificates` / `serverCertificates` / `serverSites`，清除规则的证书引用与站点配置，https 规则重置为 http，全新适配双方案；本机旧证书目录一并删除。
- 站点配置模板按方案生成：A 为 `server { listen 443 ssl; ... }`，B 为 stream 透传；证书申请弹窗与配置面板展示方案判定清单与提示。
