## 修复方案 A 申请弹窗误报 Web 服务 / 权限未满足

- 用户反馈：方案 A 申请证书时提示「未检测到 Nginx / Apache」和「当前 SSH 用户非 root 且无免密 sudo」，但服务器上确实是 nginx 且 root + 免密 sudo。
- 根因：弹窗复用 `planForInstance()`，其 `hostInfo` 来源是 `ruleHostInfo`，而该探测只在规则编辑弹窗切到「配置」标签时执行；直接从 SSL 面板申请时为空，`decideTlsPlan()` 把「探测缺失」当成「没有 Web 服务 / 没有权限」，生成 blocker 禁用提交。
- 修复：`openCertApply()` 打开弹窗后调用主进程 `tls:plan` 实时 SSH 探测并覆盖 seed plan；启用预留的 `certApplyPlanLoading`（探测中显示状态、隐藏检查项、禁用提交）、加「重新检测」按钮、用序号丢弃过期响应；`decideTlsPlan()` 区分「探测缺失」与「确实无权限」的文案。
- 验证：128 单测（新增两例）、typecheck、format:check、build、四个 Electron 回归全部通过；1440 / 1024 / 900 三档无横向溢出。

## 修复方案 A 签发后 HTTPS 仍不可访问

- 用户反馈：方案 A 证书申请成功后，服务器上的 server 块没有变成 `listen 443 ssl`，HTTPS 打不开。
- 根因：`generateSiteConfig()` 的 `secure` 只看 `rule.publicHttps`，而方案 A 的 `publicHttps` 是在 `installServerCertificate()` 部署成功后才由 `convertRulesToServerTls()` 置位；签发当下规则仍是普通 http，于是生成了 `listen 80` 模板，且写入端优先用传入模板，没回退到内置的 443 ssl 模板。
- 修复：`server-certificates.ts` 签发时传 `{ ...target.rule, publicHttps: true }`；`shared/web-include.ts` 新增 `resolveTlsSiteConfig()` 强制校验 `listen 443 ssl`，不合格就退回内置 TLS 模板；`main/web-include.ts` 写入端改调该函数并清理未用导入。
- 验证：130 单测（新增两例）、typecheck、format:check、build、四个 Electron 回归全部通过；1440 / 1024 / 900 三档无横向溢出。真实 SSH 下 nginx reload 后的公网访问仍待实机。

## 方案 A 有证书时 HTTP(80) 与 HTTPS(443) 两个 server 块共存

- 用户明确约定：一个站点规则、规则列表只显示一条；有证书时 HTTP 和 HTTPS 都要保留，不能移除 HTTP。上一条修复把方案 A 模板改成「只有 443 ssl」，导致 HTTP 访问失效。
- 修复：`site-config.ts` 的 `generateSiteConfig()` 在 `tlsMode==='server'` 时生成 `listen 80` + `listen 443 ssl` 两个 server 块；`shared/web-include.ts` 抽出 `nginxHttpServerBlock()`，新增 `mergeTlsSiteConfig()`（已有旧 TLS 配置保留用户内容、替换证书路径并补齐缺失 HTTP 块）；`main/web-include.ts` 的 `installServerCertificate()` 改用合并函数。
- 规则数据层不动：方案 A = 一条 `http + publicHttps=true`，方案 B = 一条可见 http + 隐藏 https 伴随规则，列表都只显示一条。
- 验证：131 单测、typecheck、format:check、build、四个 Electron 回归全部通过；1440 / 1024 / 900 三档无横向溢出。
