## 修复方案 A + LiteSSL 文件验证失败（validation file not found or empty）

- 根因：HTTP-01 challenge server 块（`http01.conf`）与站点配置的 HTTP server 块（`<ruleId>.conf`）都是 `listen 80` + 相同 `server_name`。nginx 对重复 server_name 只取先定义者；include `*.conf` 按文件名序加载，ruleId 是 UUID（首位 0-9a-f < h），规则块必先加载 → CA 的 challenge 请求落到规则块 `proxy_pass http://127.0.0.1:httpPort` → frps 无该路径 → 404。方案 A 下只要站点配置已存在就必然触发；方案 B 走 frpc 临时规则不受影响。
- 修复：`shared/web-include.ts` 加 `HTTP01_CONFIG_FILE='000-http01.conf'`（第4位 `-` 小于任何 hex，保证排序最前、challenge 块先定义）；`nginxHttp01ServerConfig()` 补 `location /` 回源 frps（httpPort 从 `store.server(serverId).httpPort` 取）保证验证期间正常访问不变；`main/web-include.ts` install 清旧 `http01.conf`、remove 双删，处理升级残留。
- 验证：136 单测（新增文件名排序一例）、typecheck、format:check、build、四个 Electron 回归全通过。方案 A + LiteSSL 实机重签待用户确认。

## 修复 LiteSSL EAB 账户绑定（The client lacks sufficient authorization）

- 根因：ACME 账户密钥固定存 `acme:litessl:accountKey`，EAB 变更后仍复用旧账户；LiteSSL 目录要求 EAB，CA 侧旧账户未绑定新 EAB → 下单/验证报授权不足。
- 修复：`certificates.ts` 用 EAB kid/HMAC 的 sha256 指纹记到 `acme:<provider>:accountKeyEab`，指纹变化即换新账户密钥重新注册；LiteSSL 缺 EAB 明确报错；ACME 错误附带失败端点与问题类型。`index.ts` 的 settings:save 在显式重填 EAB 时 drop 账户密钥以强制重注册。设置页补充提示。新增 2 例单测（EAB 变更换账户 / 缺 EAB 提示）。
- 验证：138 单测、typecheck、format:check、build、四个 Electron 回归全通过。真实 EAB 重签待用户确认。
